## 三、四个任务与要求的逐条对照

### 任务一 · 事件侦探（⭐ 观察记录）

`task1-detective.html` 里自带一个**真的探针**：在黑色区域按下、拖动、抬起，日志按真实顺序打印
`touchstart → touchmove × N → touchend → click`，同时用 canvas 画出你手指的轨迹（加分项）。
页面里已填好五种操作的记录表，底部有「一键复制」的纯文本答案。

**三个思考问题与答案：**

1. **一次拖动里 `touchmove` 大约触发多少次？和距离有什么关系？**
   次数由「拖动时长 × 屏幕刷新率」决定：60Hz 屏幕约每 16.7ms 一次，也就是每秒约 60 次。
   实测 0.5 秒、200px 的拖动约 25～30 次；同样距离慢慢拖 1.5 秒，会有 80～100 次。
   所以「距离越大 move 越多」只是表象——慢拖时距离和时间同时增长；快速甩动距离很大但时间短，
   事件次数反而更少。每个 `touchmove` 的坐标差就是这一帧的跟手位移。

2. **`click` 出现在 `touchend` 之前还是之后？**
   之后。顺序是 `touchstart → touchmove × N → touchend → click`，click 是浏览器在触摸序列结束后
   补发的兼容事件（历史上还会等约 300ms 判断双击）。两套都写就会「点一次执行两次」，
   应二选一，或用 `touch-action: manipulation` 去掉延迟。

3. **如果把 `touchend` 换成 `touchcancel`，会发生什么？**
   正常抬手根本不会触发 `touchcancel`（它只用于来电、通知、手势返回等系统打断），
   于是滑动判定、长按取消、拖动复位全都不执行：卡片不切换、长按定时器残留、状态卡在按下那一刻。
   正确做法是两者都监听，并共用一个清理函数。四个页面里都补了 `touchcancel`。

### 任务二 · 手势卡片（⭐⭐ 手势识别 · DOM 操作）

| 要求 | 实现 |
| --- | --- |
| 4 道菜，菜名/简介/渐变背景，底部“第 1/4 张” | 宫保鸡丁、兰州牛肉面、水晶虾饺、麻婆豆腐；计数器 + 4 个指示点 |
| `touchstart/touchend` + `changedTouches[0]` 算横向位移，阈值 40px | `GXH_THRESHOLD = 40`，并额外要求`|dx| > |dy|`，斜划不误判 |
| 左滑下一张、右滑上一张，边界提示 | toast：「已经是第一张了 / 已经是最后一张了」 |
| 容器 `touch-action: pan-y` | 横向手势归 JS，纵向仍可滚动页面 |
| 0.3s 过渡 + 300ms 冷却防跳两张 | `transition: transform .3s`；切换后上锁 300ms，一次手势最多走一张 |
| 类名/id/变量 `gxh_` 开头 | 全部遵守，文件头写了姓名学号 |

另外做了两个加分细节：指头按住时实时 `translateX`（真跟手）、到边界有 0.32 倍阻尼。

### 任务三 · 图片查看器（⭐⭐⭐ 多指手势 · 变换 · 状态管理）

- 容器 `overflow:hidden` + `touch-action:none` + `user-select:none`；
- 双指按距离比例缩放 1～4 倍，**以两指中点为基准**，公式
  `T1 = p1 − (s1/s0) × (p0 − T0)`；
- 越界只按 0.12 的系数再给一点点（阻尼），松手 0.2s 吸附回 1x/4x；
- 放大后单指拖动，`maxTx = max(0, W(s−1)/2)` 保证 1x 时拖不动；
- 双击 1x↔2x，0.25s 过渡；缩回 1x 自动居中；
- 转屏/改窗口后保留 scale，按新尺寸重算边界并夹取；
- 打开即提示「双指缩放请用手机打开」，电脑可用 Ctrl+滚轮 / 双击验证。

**“缩放不跳”的三条保证**（答辩直接背这段）：

1. 每帧都用**两指中点**做不动点重算位移，而不是以图片中心缩放；
2. 状态只有 `scale / tx / ty` 三个数，统一由 `gxh_apply()` 写回样式；
3. 每次 `touchstart` 以当前值作为基准快照（不做逐帧累乘），并且过渡动画没走完时不接管，
   避免把画面“冻”在半路。

### 任务四 · 摇一摇彩蛋（⭐⭐⭐⭐ 设备能力 · 权限 · 降级）

- `devicemotion` → `accelerationIncludingGravity` 算合成加速度 `a = √(x²+y²+z²)`；
- `a > 18` 判定摇动，触发后 **1.5s 冷却**，同一次不会连续重复同一道菜；
- 结果卡带弹出动画 + 震感反馈；
- iOS 13+ 暴露 `requestPermission`：页面显示「开启体感权限」按钮，在点击手势里申请；
- 拿不到事件 / 字段全 null / 2.5 秒没有数据 → 判定不可用，显示
  「当前设备不支持，请用手机打开」/「收不到传感器数据（可能未授权，或本机没有加速度计）」，
  并**始终保留「点我抽一次」按钮**作为降级方案。

**为什么必须做降级：** 桌面浏览器没有加速度计，`devicemotion` 可能永远不触发、或字段全是 `null`；
iOS 13+ 没授权就拿不到数据；安卓隐私设置也会屏蔽。只写监听不兜底，页面就是一块“点了没反应”的死屏。

**两个字段的区别：** `accelerationIncludingGravity` 含重力，静置时合成值约 9.8，所以阈值取 18
（≈1.8 倍重力）；`acceleration` 已扣掉重力，静置接近 0，适合计步/精确晃动强度，但部分机型为 `null`，必须判空。

## 六、踩过的坑与解决办法

1. **双指缩放第一帧会“跳一下”**
   原因：`touchstart` 没清空上一轮的 `lastDist`，第一帧拿残留距离做比较，比例算错。
   解决：每次手势开始都记录 `startDist / startMid / startScale / startTx` 作为基准，
   用 `T1 = p1 − (s1/s0)(p0 − T0)` 统一算缩放 + 双指平移。
   后来还发现：过渡动画（双击/回弹）没走完时手指按下去，读到的 transform 是中间值，
   画面会“冻”在半路——改成动画进行中不接管手势。

2. **快速连滑一次跳了两张卡**
   原因：一次滑动可能连续触发两次判定，`index` 被加了两次。
   解决：切换后上 300ms 冷却锁（与 0.3s 过渡对齐），锁内忽略新手势；
   另外先做轴向判断，纵向滑动直接交还页面滚动，不参与切换。

3. **任务四在电脑上“没反应”**
   原因：桌面没有加速度计，`devicemotion` 不触发；而 Chrome 又暴露了 `requestPermission`，
   首屏会停在“要授权”的状态。
   解决：改成「先挂监听 → 2.5s 无数据判定不可用 → 显示文案 + 授权按钮 + 降级按钮」，
   并且区分“没授权”和“没有传感器”两种提示。

4. **视频位自动探测在 `file://` 下报错**
   原因：`fetch` 在 `file://` 被浏览器拦截，控制台出现一条网络错误。
   解决：`location.protocol === 'file:'` 时跳过探测，直接信任 `<video>`；文件缺失时用 `<source>` 的 `error` 事件退回提示卡。

5. **手机上录的屏放不出来，画面全黑**
   原因：安卓录屏默认编码是 HEVC / H.265（`hvc1`），Chrome 桌面版不解码 HEVC，只出黑屏。
   解决：`ffmpeg -c:v libx264 -pix_fmt yuv420p -movflags +faststart` 转成 H.264（`avc1`），
   体积也从“原始”压到 ~1.8MB，顺便用 `-ss 2.5 -frames:v 1` 抽了一帧当封面。
